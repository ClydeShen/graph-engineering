<objective>
Implement the OCC Writable CTE — the core atomicity mechanism. A single SQL statement computes the SHA-256 version_hash via pgcrypto, claims the `(predecessor_hash, scope_id)` slot, and on conflict performs atomic causal inversion (loser repointed to winner) — all in one transaction with no application callback and no `::jsonb` conversion.

Purpose: This is the integrity gate of the entire system (REQ-02). Every Worker and the Gateway write through this path. Idempotency (REQ-18) via ON CONFLICT DO NOTHING on the version_hash unique key.
Output: `occWrite()` helper + SQL template + integration tests proving won/demoted and idempotency.
</objective>

The INSERT computes `version_hash = encode(digest($1::text || '|' || $2::text || '|' || $3::text || '|memory_updated|' || $4::text, 'sha256'), 'hex')` and stores `payload = $4::text` (NEVER `::jsonb`). The DO UPDATE branch sets `event_type='conflict_detected'`, rewrites `predecessor_hash` to the winner's version_hash (subquery selecting the existing memory_updated row), recomputes `version_hash` with `event_type='conflict_detected'` using the SAME `$4` canonical_json_text, sets `payload=$4::text`. Final SELECT returns `version_hash` and `occ_result` CASE mapping `memory_updated`→`won`, `conflict_detected`→`demoted`. Add a parallel `OCC_WRITE_DO_NOTHING_SQL` variant using `ON CONFLICT (scope_id, entity_id, version_hash) DO NOTHING` for idempotent re-delivery (REQ-18).
