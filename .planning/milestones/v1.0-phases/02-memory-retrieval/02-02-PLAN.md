<objective>
Implement EpisodicMemoryWorker — the first Phase 2 memory worker — which records execution event traces into `episodic_memory` and satisfies Phase 1 constraint C1 by also appending a `memory_updated` event to `execution_event_log` after every INSERT.

Purpose: Episodic memory is the raw material for all downstream memory tiers. Without episodic records, the MemorySynthesizerWorker has nothing to distill, and G3-1 cannot pass.

Output: `episodic.worker.ts` (worker + trigger config), `episodic.worker.test.ts` (unit tests covering G3-1), and extension of `packages/workers/src/index.ts` with the new registration block.
</objective>

  ```
  await this.pool.query(
    `INSERT INTO episodic_memory (scope_id, entity_id, content, created_at)
     VALUES ($1, $2, $3, NOW())`,
    [scopeId, entityId, writeGuard(content)],
  );
  ```
  Critical: do NOT include `ts_doc` in the INSERT column list — it is `GENERATED ALWAYS AS ... STORED`. Including it causes: `ERROR: column "ts_doc" can only be updated to DEFAULT`.

  Step 2 — Phase 1 constraint C1: fire memory_updated event to execution_event_log:
  ```
  const contentHash = createHash('sha256').update(content).digest('hex');
  await occWrite(this.pool, {
    scopeId,
    entityId,
    predecessorHash,
    payload: { memory_type: 'episodic', content_hash: contentHash },
    eventType: 'memory_updated',
  });
  ```
  Add comment above occWrite call: `// Phase 1 constraint C1 — every memory write must trace to execution_event_log`

  Error propagation: no try/catch in onEvent — errors propagate to iii-sdk caller which handles retry. This matches the frontier.worker.ts pattern.

  C1 best-effort decision: INSERT and occWrite are sequential, not transactional. If occWrite fails
  after INSERT commits, the episodic row is orphaned with no event_log entry. This is accepted:
  wrapping both in BEGIN/COMMIT would require occWrite to accept a PoolClient (out of scope here);
  occWrite already uses OCC semantics so conflicts are surfaced, not silently lost.
  </action>

  ```
  // Writes to episodic_memory on task_spawned/memory_updated events.
  // Phase 1 constraint C1: also fires memory_updated event to execution_event_log.
  const episodicWorker = new EpisodicMemoryWorker(pool);
  worker.registerFunction('graph::memory::episodic', async (payload: unknown) => {
    const p = payload as {
      scope_id: string;
      entity_id: string;
      content: string;
      predecessor_hash: string;
    };
    await episodicWorker.onEvent(p.scope_id, p.entity_id, p.content, p.predecessor_hash);
    return { written: true };
  });
  worker.registerTrigger(EPISODIC_TRIGGER_CONFIG);
  ```

The four fields (`scope_id`, `entity_id`, `content`, `predecessor_hash`) are what the caller publishes to the `graph::memory::episodic::ingest` topic. Casting with `as { ... }` without runtime Zod validation matches the existing frontier.worker.ts pattern (iii-sdk guarantees topic-level schema; full runtime validation is a Phase 3 hardening task).
