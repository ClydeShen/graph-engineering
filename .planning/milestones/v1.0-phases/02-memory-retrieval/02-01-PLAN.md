  Create `migrations/006-memory-extensions.sql`. The file must follow the comment header style of `migrations/005-scope-lineage.sql` exactly (opening block comment, section dividers with `── table_name ──` dashes).

  Use `ADD COLUMN IF NOT EXISTS` for every column — migration 003 has no `dedup_hash`, no `superseded_by`, no `reinforcement_count`, no `entity_id`. Verify against migration 003 before writing to confirm zero duplicates.

  Required changes per table:

  **episodic_memory** — ADD COLUMN IF NOT EXISTS:
  - `entity_id UUID` (links episodic records back to the entity in execution_event_log; nullable, no FK constraint — scopes may be closed before entity exists in event log)
  - `intent_summary TEXT` (optional distillation field written by SemanticMemoryWorker; nullable)
  - `outcome_summary TEXT` (optional distillation field; nullable)

  **semantic_memory** — ADD COLUMN IF NOT EXISTS:
  - `superseded_by UUID` (self-referential; nullable; used by logical-delete pattern — `superseded_by = id` marks a record as expired)

  Then add HNSW index on `semantic_memory.embedding` — migration 003 deliberately deferred this:
  ```
  CREATE INDEX IF NOT EXISTS idx_semantic_memory_embedding_hnsw
    ON semantic_memory
    USING hnsw (embedding vector_cosine_ops)
    WITH (m = 16, ef_construction = 64)
    WHERE embedding IS NOT NULL;
  ```
  (Partial index `WHERE embedding IS NOT NULL` prevents HNSW from indexing NULL vectors — per RESEARCH.md Pitfall 5.)

  **procedural_memory** — ADD COLUMN IF NOT EXISTS:
  - `success_count INT NOT NULL DEFAULT 0` — reinforcement increment counter (ADR 20 Task 1)
  - `failure_count INT NOT NULL DEFAULT 0` — tracked for quality_score computation
  - `reinforcement_count INT NOT NULL DEFAULT 0` — Ebbinghaus decay check column (G3-6 criterion)
  - `last_used_at TIMESTAMPTZ NOT NULL DEFAULT NOW()` — Ebbinghaus decay 90-day window
  - `superseded_by UUID` — nullable; logical-delete pattern, `superseded_by = id` marks decay

  Note: `quality_score FLOAT DEFAULT 0.5` and `is_anti_pattern BOOLEAN DEFAULT FALSE` already exist in migration 003 — do NOT add them again.

  **working_memory** — ADD COLUMN IF NOT EXISTS:
  - `dedup_hash TEXT` — nullable (existing rows from Phase 1 have no hash; new inserts always provide one)

  Then add partial unique index:
  ```
  CREATE UNIQUE INDEX IF NOT EXISTS idx_working_memory_dedup
    ON working_memory (scope_id, dedup_hash)
    WHERE dedup_hash IS NOT NULL;
  ```
  (Partial unique index: only enforces uniqueness when `dedup_hash IS NOT NULL`, so pre-existing NULL rows do not violate the constraint.)

  **ts_doc dictionary resolution** — the `'english'` vs `'simple'` dictionary mismatch (migration 003 uses `to_tsvector('english', ...)` but ADR 20 supplement specifies `plainto_tsquery('simple', ...)` for BM25 queries) is resolved as follows: do NOT change the GENERATED ALWAYS column in this migration. Changing a GENERATED ALWAYS column requires DROP + ADD and would destroy the existing GIN index and all ts_doc values, requiring full table rewrite. The query-side will use `plainto_tsquery('english', ...)` consistently to match the stored vector. Add a comment at the top of migration 006 documenting this decision:
  ```sql
  -- ts_doc dictionary: Migration 003 uses to_tsvector('english', ...) for column generation.
  -- BM25 queries in Phase 2 use plainto_tsquery('english', ...) to match the stored tsvector.
  -- The ADR 20 supplement specified 'simple' to preserve technical terms; however, changing
  -- GENERATED ALWAYS columns requires DROP+ADD which destroys the GIN index. Accepted tradeoff:
  -- 'english' stemming may normalize technical terms but the GIN index remains intact.
  -- Decision: use plainto_tsquery('english', ...) in all Phase 2 BM25 search queries.
  ```

  End the migration with a comment noting the migration number and what Phase it enables.
