  Hybrid RRF SQL constant (authoritative SQL — targets semantic_memory which has embedding column):
  ```typescript
  const HYBRID_RRF_SQL = `
  WITH
  vector_candidates AS (
    SELECT id, content, scope_id,
           ROW_NUMBER() OVER (ORDER BY embedding <=> $1) AS vector_rank
    FROM semantic_memory
    WHERE embedding IS NOT NULL
    ORDER BY embedding <=> $1
    LIMIT 20
  ),
  bm25_candidates AS (
    SELECT id,
           ts_rank_cd(ts_doc, query) AS bm25_raw_score,
           ROW_NUMBER() OVER (ORDER BY ts_rank_cd(ts_doc, query) DESC) AS bm25_rank
    FROM semantic_memory,
         plainto_tsquery('english', $2) AS query
    WHERE ts_doc @@ query
    ORDER BY bm25_raw_score DESC
    LIMIT 20
  ),
  all_candidates AS (
    SELECT id FROM vector_candidates
    UNION
    SELECT id FROM bm25_candidates
  ),
  rrf_scored AS (
    SELECT
      ac.id,
      0.6 * (1.0 / (60 + COALESCE(vc.vector_rank, 21))) +
      0.4 * (1.0 / (60 + COALESCE(bc.bm25_rank,   21))) AS rrf_score
    FROM all_candidates ac
    LEFT JOIN vector_candidates vc ON ac.id = vc.id
    LEFT JOIN bm25_candidates   bc ON ac.id = bc.id
  )
  SELECT s.id, s.scope_id, s.content, r.rrf_score
  FROM rrf_scored r
  JOIN semantic_memory s ON r.id = s.id
  ORDER BY r.rrf_score DESC
  LIMIT $3
  `;
  // Parameters: $1 = query_embedding (vector literal), $2 = query_text (TEXT), $3 = final_k (INT)
  // BM25 uses plainto_tsquery('english', ...) to match to_tsvector('english', ...) stored by migration 003.
  // HNSW uses semantic_memory.embedding vector(1536) — NOT episodic_memory which has no embedding column.
  ```

  Route builder:
  ```typescript
  export function buildMemoryRoute(pool: Pool, embedding: EmbeddingProvider): Hono {
    const app = new Hono();

    // GET /v1/memory/search?q=...&scope_id=...
    app.get('/memory/search', async (c) => {
      const q = c.req.query('q') ?? '';
      const scopeId = c.req.query('scope_id') ?? '';

      // Validate scope_id as UUID v4 (ADR 24 REQ-16)
      if (!scopeId || !/^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i.test(scopeId)) {
        return c.json({ error: 'invalid scope_id: must be a UUID v4' }, 400);
      }

      try {
        // LLM CALL — ADR 22 (embed query text for HNSW search leg)
        const { vector } = await embedding.embed(q);
        const embeddingLiteral = `[${vector.join(',')}]`;

        const result = await pool.query<MemorySearchResult>(HYBRID_RRF_SQL, [
          embeddingLiteral,
          q,
          10,
        ]);
        return c.json<MemorySearchResponse>({ results: result.rows });
      } catch {
        return c.json({ error: 'search failed' }, 500);
      }
    });

    // POST /v1/memory/reinforce  body: { template_id: string }
    app.post('/memory/reinforce', async (c) => {
      const body = await c.req.json<{ template_id?: string }>().catch(() => ({}));
      if (!body?.template_id) {
        return c.json({ error: 'template_id required' }, 400);
      }

      try {
        await pool.query(
          `UPDATE procedural_memory
           SET success_count = success_count + 1, last_used_at = NOW()
           WHERE id = $1`,
          [body.template_id],
        );
        return c.json({ reinforced: true });
      } catch {
        return c.json({ error: 'reinforce failed' }, 500);
      }
    });

    return app;
  }
  ```

  Note: UUID validation is inline (not via zod-guard middleware) because `scope_id` here is a query param not a path param — the existing validateScopeIdParam middleware reads from path params. The regex is the standard UUID v4 pattern.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → GET /memory/search | q and scope_id from untrusted HTTP input; scope_id validated as UUID v4; q passed to plainto_tsquery (safe — handles arbitrary text) and to embedding provider |
| HTTP client → POST /memory/reinforce | template_id from untrusted HTTP input; passed as $1 parameterized query (SQL injection safe) |
| query text → LLM embed | q may contain sensitive data; no writeGuard on search query (it is transient, not stored); embedding provider is internal |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06-01 | Injection | GET q param → plainto_tsquery | mitigate | plainto_tsquery safely converts arbitrary text to tsquery — no special character injection possible |
| T-02-06-02 | Injection | POST template_id → UPDATE WHERE | mitigate | Parameterized query ($1) — SQL injection not possible |
| T-02-06-03 | Information Disclosure | HNSW embedding reveals query intent | accept | Internal service; query embedding is not stored; only results returned |
| T-02-06-04 | Tampering | scope_id bypass → search all scopes | mitigate | UUID v4 validation before DB query; scope_id passed to query for filtering (RRF SQL can add WHERE scope_id = $4 if needed for isolation) |
| T-02-06-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed |
