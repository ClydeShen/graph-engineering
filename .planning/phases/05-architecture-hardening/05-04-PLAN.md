  try {

  }
}

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ~/.memex/config.json → process | File is user-owned; contents are read as text and parsed — no eval, no dynamic code execution |
| ${ENV_VAR} interpolation | Environment variable values are substituted into JSON strings; attacker controlling env vars already has process access |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-04-01 | Information Disclosure | apiKey values in config | accept | Config file is user-owned (~/.memex/); Gateway process reads it at boot; keys never written to logs (Zod schema does not log parsed values) |
| T-05-04-02 | Tampering | Malformed config.json causes null return | accept | Null return causes Gateway to fall back to env vars — deliberate design; no crash |
| T-05-04-03 | Elevation of Privilege | Path traversal via configPath param | mitigate | loadMemexConfig() default path is fixed; callers passing a custom path are internal (test-only); no user input reaches this parameter in production code |
| T-05-04-SC | Tampering | npm installs | mitigate | No new packages — uses zod (already in shared) and Node built-ins only |
</threat_model>
