    Create packages/gateway/src/routes/skills.ts.

    Function signature: `export function buildSkillsRoute(skillsDir = process.env['SKILLS_DIR'] ?? './skills'): Hono`

    No Pool parameter — this route reads from the filesystem, not the database.

    Module-level cache variables (scoped within the module, not the function, so they persist across requests):
    - `let cachedList: SkillSummary[] | null = null`
    - `let cachedMtime = 0`

    Export SkillSummary interface: `{ fingerprintId: string; name: string; description: string }`

    parseFrontmatter(content: string): { name: string; description: string; fingerprintId: string } — private helper:
    - Split on '---', extract the block at index 1 (the frontmatter block)
    - Split that block on '\n'
    - For each of name, description, fingerprint_id: find the line starting with that key, slice off 'key: ', trim
    - Return { name, description, fingerprintId } (note: file uses 'fingerprint_id', return as 'fingerprintId')

    GET /skills handler:
    1. statSync(skillsDir) to get current mtimeMs; catch ENOENT → return c.json({ skills: [] })
    2. If cachedList !== null AND dirStat.mtimeMs <= cachedMtime: return cached list (use <= to check staleness, i.e. invalidate when mtimeMs > cachedMtime per the Windows constraint)
    3. Else: readdirSync(skillsDir, { withFileTypes: true }) → filter for directories → for each, read skillsDir/{entry.name}/SKILL.md via readFileSync → catch per-file errors (skip the file, log warning) → parseFrontmatter → build SkillSummary
    4. Update cachedList and cachedMtime = dirStat.mtimeMs
    5. Return c.json({ skills: cachedList })

    GET /skills/:id handler:
    - id = c.req.param('id')
    - SECURITY: validate id matches /^[0-9a-f]{64}$/ before constructing any path. If it does not match, return c.json({ error: 'invalid id' }, 400) immediately. This prevents path traversal (T-05-05-01).
    - path = join(skillsDir, id, 'SKILL.md')
    - Try readFileSync(path, 'utf8'), return c.json({ content: fileContent })
    - Catch: return c.json({ error: 'not found' }, 404)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| skillsDir filesystem → HTTP response | SKILL.md files are written by internal LessonSaveWorker; route reads them read-only and forwards content to callers |
| GET /v1/skills/:id parameter | The id path parameter is used to construct a filesystem path — path traversal must be prevented |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05-01 | Elevation of Privilege | Path traversal via :id parameter | mitigate | Validate that id matches /^[0-9a-f]{64}$/ (SHA-256 hex) before constructing the path — reject with 400 if it does not match |
| T-05-05-02 | Information Disclosure | SKILL.md content forwarded verbatim | accept | Skills are internal lessons written by the runtime; no external secrets are stored in SKILL.md files |
| T-05-05-03 | Denial of Service | Large skills directory scan on cache miss | accept | readdirSync is synchronous; for typical skill counts (<1000) this is sub-millisecond; mtime cache limits re-scan to once per directory change |
| T-05-05-SC | Tampering | npm installs | mitigate | No new npm packages — uses Node built-ins (fs, path, os) and existing Hono |
</threat_model>
