Implement `classifyProviderError()` and `FallbackProvider` — the circuit-breaker layer for LLM provider failover.

Output: Two new files in `packages/shared/src/llm/`, one test file, and a barrel re-export update.

  <behavior>
    - FallbackProvider.chat() returns the first successful provider response
    - When provider throws a shouldThrow error (auth), the error is re-thrown immediately (second provider is NOT called)
    - When provider throws a shouldFailover error (rate_limit), the next provider is tried
    - When all providers are exhausted, AllProvidersExhaustedError is thrown
    - Providers are tried in ascending priority order (priority:1 before priority:2)
    - LLM CALL annotation appears at every site that delegates to a concrete provider.chat()
  </behavior>
  <action>
    Create packages/shared/src/llm/fallback.provider.ts. It implements LLMProvider exactly:
    `chat(messages: ChatMessage[], opts?: { temperature?: number }): Promise<string>`

    Export ProviderEntry interface: `{ name: string; provider: LLMProvider; priority: number }`
    Export AllProvidersExhaustedError extends Error (message: "All LLM providers exhausted").
    Export FallbackProvider class implementing LLMProvider.

    Constructor: `constructor(private readonly providers: ProviderEntry[])`
    Sort providers by priority ascending at construction time (do not mutate input array).

    chat() implementation — iterate sorted providers:
    ```
    for each entry:
      try:
        // LLM CALL — justified by ADR 22 (Workers call provider interface, not raw HTTP)
        result = await entry.provider.chat(messages, opts)
        return result
      catch err:
        classified = classifyProviderError(err)
        if classified.shouldThrow: throw classified.original
        if classified.shouldFailover: continue
    throw new AllProvidersExhaustedError()
    ```
