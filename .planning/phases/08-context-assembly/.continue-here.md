## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Type-only re-export → runtime re-export breaks vitest alias resolution | `packages/shared/src/types.ts` re-exports from `@graph/types/api`. As long as ALL re-exports there are `export type { ... }` (type-only), Vite never resolves `@graph/types/api` as a module — it's erased at compile time. The moment ANY value (non-type) export is added (as we just did for `CANONICAL_EVENT_TYPES`), Vite must resolve `@graph/types/api` at runtime, which requires an alias in `vitest.config.ts`. | advisory | Before adding any new value-level cross-package re-export touching `@graph/types/*` (or any `@graph/*` package not yet in `vitest.config.ts`'s `resolve.alias`), run `npx vitest run` afterward — don't rely on `tsc -b` alone, it doesn't catch Vite module-resolution gaps. |
| Two competing vitest configs | Repo has both `vitest.config.ts` (manual `resolve.alias`, no `@graph/types/*` until this session) and `vitest.config.mts` (uses `vite-tsconfig-paths`, which would have covered `@graph/types/*` automatically). `vitest.config.ts` is the one actually picked up by `npx vitest run`. | advisory | If touching test config, be aware `.mts` may be dead/leftover from an architecture-review run — don't assume it's active. Not investigated/resolved this session; out of scope for Phase 8. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
