<objective>
Extend FrontierSchedulerWorker (ADR 31) so that when a frontier task declares `required_skills[]` in its payload, dispatch is gated on the existence of at least one active, fresh-heartbeat agent in `agent_registry` whose `skills` array overlaps the task's `required_skills` (GIN `&&` operator). This satisfies GATE4-5 — tasks are dispatched by skill match, not arbitrary assignment — and enforces D-1 (no explicit agent assignment).

Purpose: D-1 (LOCKED) makes FrontierScheduler the sole task-dispatch authority. Skill routing is how the scheduler decides which tasks are eligible for dispatch when capable agents exist. This is the dispatch-side half of the agent_registry foundation (the MCP register_agent tool in Plan 05 is the write side).

Output: an extended `frontier.worker.ts` with an opt-in skill-matching filter layered on the existing Top-K SQL (priority formula untouched per ADR 31 + CONTEXT.md surgical-change constraint), and extended `frontier.test.ts` covering skill-match, no-skill-passthrough, and no-capable-agent cases.
</objective>
