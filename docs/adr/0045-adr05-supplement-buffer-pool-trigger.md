# ADR 05 Supplement｜Pre-Create Buffer Pool — Trigger Conditions and Pool Size

status: accepted
日期: 2026-06-05
supplements: ADR 05 (Scope 筑巢协议：三阶段控制面前置 DDL)

---

## 上下文

ADR 05 规定高频长周期任务可以开启**预创建缓冲池**（pre-create buffer pool）：在系统低谷期预物化未来 N 个空白 Scope 分区，规避 DDL 锁在高并发入口的等待延迟。

ADR 05 原文未定义：
1. "高频"的量化触发标准
2. 预创建池大小 N 的计算依据
3. 池耗尽时的降级行为

本补充 ADR 填补上述三项空白。所有阈值基于系统 Phase 1 设计容量估算，须在生产数据积累后复核。

---

## 决策

### 触发条件：何为"高频"

**触发标准**（任一满足即视为高频）：

| 条件 | 阈值 | 说明 |
|------|------|------|
| Scope 启动速率 | ≥ 10 个 Scope/分钟，持续 ≥ 3 分钟 | 滑动窗口均值；瞬间峰值不触发 |
| 待处理 Scope 队列深度 | ≥ 5 个 Scope 在 DDL 环节排队 | 控制面独占连接池排队长度 |

控制面守护线程在每次完成一批筑巢操作后，检查上述条件。若满足，进入**低谷期预创建模式**（预创建定时器，每 30 秒执行一次，直至不再满足触发条件）。

**低谷期判断**：当前队列深度 = 0（无待处理 Scope）且距上次 DDL 操作 ≥ 15 秒，视为低谷期。

---

### 池大小：N 的计算

```
N = max(ceil(observed_spawn_rate_per_minute × 2), 5)
```

其中 `observed_spawn_rate_per_minute` 为过去 5 分钟的 Scope 启动速率均值。

**示例**（供参考，非硬编码）：

| 观测速率 | N |
|----------|---|
| < 5 个/分钟 | 5（最小池） |
| 10 个/分钟 | 20 |
| 20 个/分钟 | 40 |

N 上限（Phase 1）：50。超出此值视为异常流量，池大小钳制到 50 并告警。

---

### 池耗尽时的降级行为

池耗尽（已无预创建分区可用）时，系统**透明降级**为标准三阶段筑巢协议（ADR 05 原始流程）：

1. 控制面正常执行独占 DDL（同步创建分区）
2. 日志记录一条 `WARN: buffer_pool_exhausted, falling back to on-demand DDL`
3. **不抛出错误，不中断业务流量**

业务侧对降级**无感知**——延迟略高，但正确性不受影响。

---

### 预创建分区的命名与 GC

预创建的空白分区以 `pre_{uuid}` 命名，其中 `uuid` 为提前生成的 Scope UUID。当控制面消费一个预创建分区时：
1. 从池队列取出 `pre_{uuid}`
2. 将其标记为活跃 Scope（写入 `scope_lineage`）
3. 注入 `plan_created` 首个事件

若预创建的分区在 **24 小时内**未被消费（表示预测失败），控制面 GC 定时器执行：
1. DROP PARTITION（独占 DDL 连接）
2. 从池队列移除

---

## 初始估算声明

> **本补充 ADR 中所有阈值（10 Scope/分钟、N = rate × 2、上限 50、24 小时 GC 窗口）均为基于设计容量的初始估算。应在系统运行 4 周后，依据实测的 Scope 启动速率分布进行复核和修订。**

---

## 后果

- 高频场景下 Scope 启动延迟降低（DDL 锁等待从热路径移至后台）
- 低谷期增加少量后台 DDL 操作（可接受）
- 池耗尽时降级行为保证了系统在任何流量模式下的正确性
- 池 GC 防止空白分区永久积压
